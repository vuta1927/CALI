- B1 backend BE-001/002 (code + tests, reviewed; PO accepted ADR-068 on 2026-11-09). Catalog: `GET /v1/exercises` (published only, keyset cursor on `(slug, id)`, `limit` 1..100, default 50), `GET /v1/exercises/{id}` and `GET /v1/criteria-config` (ETag `"c{criteriaVersion}.i{indicatorSetVersion}"`, `If-None-Match` → 304, `Cache-Control: public, max-age=300`). These three are anonymous and use a new per-client-IP rate limit policy `public` (default 120 requests/minute, `RateLimiting:Public`, 429 + `Retry-After`). Media `url` stays null until signed media URLs (new backlog task BE-006). Plans: `GET /v1/plans` returns the caller's non-deleted revisions, keyset cursor on `(created_at, id)` (opaque, at most 512 characters; a malformed cursor or `limit` is 400). Revisions created mid-walk appear on later pages and none are skipped or repeated, because `POST /v1/plans` writes `created_at = clock_timestamp()` after taking the per-user `user_sync_state` lock. `POST /v1/plans` creates a root revision (revision 1, `current`, `lineageId = id`), validates with the same rules as sync push (400 `validation_failed` with errors keyed by field path), and writes a gap-free `sync_change_log` (plan, workouts, exercises) in one transaction. Errors: 404 `user_not_found`, 409 `conflict` (an id already in use, including by another user, without leaking it) or `plan_count_limit`, 413 for bodies over 1 MiB, 415 for non-JSON or non-UTF-8 bodies, 429 per user through the `sync` policy. Idempotency (ADR-068): the `Idempotency-Key` header (uuid) is required. `db/009_http_idempotency.sql` adds `http_idempotency_keys` (per user; only successful responses, stored in the same transaction) and the partial index `idx_training_plans_user_created`. A repeat with an equivalent body (same canonical JSON: key order, whitespace and number formatting do not matter) replays the stored 201 body. The same key with a different body is 409 `idempotency_key_reused`. A failed request stores nothing, so it can be retried with the same key. OpenAPI documents the new 400/401/404/413/415/429 responses. Tests: unit tests, contract tests for all five endpoints (`SchemaValidator` now treats Microsoft.OpenApi's YAML `null` enum sentinel as JSON null), and integration tests. The integration tests cover IDOR (including replaying another user's cursor), stable pagination under inserts during a walk, idempotent replay and key reuse, headers, limits, rate limiting, and the 008→009 upgrade path. Local run: Unit 126, Contract 54, Integration 165, all passing. docs 07, 13, 15, 20 and `contracts/backlog.csv` updated.
